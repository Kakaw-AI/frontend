---
title: How it works
description: What happens between your question and the answer.
---

Every question goes through the same steps. You can watch them as they happen: each step appears above the answer while Kakaw works. When the answer is done, the list folds into one line, like *5 steps · 8.4s*; click it to open it again. A failed answer keeps the list open.

## 1. Understand the question

A follow-up like *"what about 2025?"* is rewritten into a complete question using the conversation, so *"what about 2025?"* after a question about orders becomes *"how many orders were there in 2025?"*. A greeting gets a reply without touching the database.

## 2. Write the query

The model writes one read-only query: a `SELECT` statement for PostgreSQL and SQLite, or an [aggregation pipeline for MongoDB](/docs/data/mongodb). It sees your schema (tables or collections, columns or fields, keys, sample values) and, when there are any, questions this database has answered correctly before together with the query that worked.

If the question can be read more than one way (*"best customers"* by revenue or by number of orders?), Kakaw asks which you mean instead of guessing, with the choices as buttons.

## 3. Run and repair

The query runs read-only, with a 30-second limit and up to 200 rows. If it fails, the error goes back to the model and it writes a corrected query. A filter that names a value your data doesn't hold, such as `'cancelled'` for `'Cancelled'`, is fixed without another model call.

A query that joins lists can repeat itself: every URL of a person once per tag, or the person's name and details on every row of their list. When the rows repeat like that, the model rewrites the query once so each thing appears once. Whatever still repeats after that is cleaned up before you see it: exact copies are removed, and a value that is the same on every row, such as the person's name, is shown on the first row only.

## 4. Review the result

A second, quick model call checks that the result answers the question: the right table, filters, time range and grouping. A clear mistake sends the query back for one more rewrite.

The review also decides whether the data is enough on its own. When the question needs facts from outside your database, or newer than it, Kakaw [searches the web](/docs/web-search) as well.

## 5. Answer

The model writes a short summary of the result. At the same time Kakaw plans a chart when the data suits one, and suggests follow-up questions. The table, the chart and the query appear with the answer.

## What Kakaw remembers

When an answer is completed, the question and the query that answered it are kept for that database. The next similar question starts from that query, which makes answers faster and more consistent. This memory belongs to one database of one user, and it stops applying to a question once its query uses a table or column the database no longer has.
