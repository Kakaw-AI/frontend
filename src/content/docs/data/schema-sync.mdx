---
title: Schema sync
description: How Kakaw learns the structure of your database, and what it keeps.
---

Before the first question, Kakaw reads the structure of your database. Every answer starts from this.

## What it reads

- Tables and their row counts
- Columns, their types and whether they can be empty
- Primary keys, foreign keys and indexes
- A few sample rows per table and sample values per column
- For MongoDB, which has no fixed columns: the fields of up to 100 sampled documents per collection. See [MongoDB](/docs/data/mongodb).
- Every value of a short text column, such as category names, statuses or countries: up to 50 distinct values of 60 characters or less, in tables of up to 200,000 rows. Columns whose name suggests a secret (password, token, key and similar) are skipped.

From these Kakaw builds short notes about each table and how the tables relate, which help the model pick the right tables and the exact values stored in a column. When you name a value, such as *"Home Decor"*, the model can match it to the stored value instead of guessing. It doesn't copy your tables: answers come from queries that run on your database when you ask, and their results are kept with the chat. See [Privacy and security](/docs/privacy-and-security).

## Status

The sync page shows the progress. A database moves through:

| Status | Meaning |
| --- | --- |
| Indexing | Kakaw is reading the schema. Usually a few seconds. |
| Ready | You can ask questions about it. |
| Failed | The sync stopped. The page shows why and offers **Try again**. |

A sync that runs longer than five minutes is marked failed, so you can retry instead of waiting.

## When your schema changes

Kakaw works from the schema it read. After you add, rename or drop tables or columns in a PostgreSQL database, or collections and fields in a MongoDB database, open **Databases** and choose **Resync** next to it. Kakaw reads the structure again, and its chats pause until the status is back to Ready. You can resync once every 30 seconds. Questions remembered for the old structure are not reused for the new one.

An uploaded SQLite file doesn't change, so it has no **Resync**. Upload the new file as another database.

## More than one database

Use **Databases** in the sidebar to connect another. It shows the sync page too, and opens chat once it is ready. Each chat belongs to one database, and the sidebar groups your chats by database.

To remove a database, choose **Delete** next to it in **Databases**. Its chats, schema, remembered questions and stored credentials or uploaded file go with it. The tokens its chats used stay in your profile totals.
